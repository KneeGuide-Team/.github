# Security Policy

KneeGuide is a healthcare-technology prototype. Security reports are handled carefully to reduce risk to users, infrastructure and any future rehabilitation data.

## Supported scope

Security reports may cover the current default branches of:

- `KneeGuide-Team/kneeguide-frontend`
- `KneeGuide-Team/kneeguide-backend`

Prototype, planned and mock functionality documented as non-operational is outside production-support guarantees, but credible architectural risks are still welcome.

## Reporting a vulnerability

Do **not** publish an exploitable vulnerability, credentials, personal data or medical information in a public issue.

Use GitHub's private vulnerability reporting feature when available. If private reporting is unavailable, contact the organization owner through the verified contact method shown on the GitHub organization profile and include only the minimum information needed to establish a secure communication channel.

Please provide:

- A concise description and affected repository/component.
- Reproduction steps using synthetic, non-sensitive data.
- Potential impact.
- Suggested mitigation, if known.
- Whether the issue is already public.

## Responsible disclosure

Allow the maintainers reasonable time to investigate and remediate before public disclosure. Do not access, alter or retain data that does not belong to you. Do not perform denial-of-service testing or target third-party services such as hosting, email or database providers.

## Sensitive information

Never send passwords, OTP values, JWTs, private keys, database credentials, real patient records or other regulated/sensitive information in an issue or pull request.

This policy is not a statement of regulatory certification or a service-level guarantee.
